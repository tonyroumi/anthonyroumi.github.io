Baselines

Recall the policy gradient estimator:

\[ \nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta} \left[ \nabla_\theta \log \pi_\theta(a \mid s)\,R(\tau) \right]. \]

This estimator is unbiased, but it can have very high variance, especially when the return comes directly from the environment. The baseline's job is variance reduction.

Given a baseline value \(b\), we can form the estimator

\[ \nabla_\theta J(\theta) \approx \hat{g} = \frac{1}{m} \sum_{i=1}^{m} \nabla_\theta \log p\bigl(\tau^{(i)};\theta\bigr) \bigl(R(\tau^{(i)}) - b\bigr). \]

Intuitively, we want to increase the probability of trajectories whose return is better than average and decrease the probability of trajectories whose return is worse than average.

This estimator remains unbiased as long as the baseline does not depend on the sampled action.

Why the Baseline Does Not Change the Expected Gradient

If \(b\) is constant with respect to the sampled action, then the extra term has zero expectation:

\[ \begin{aligned} \mathbb{E}\!\left[\nabla_\theta \log p(\tau;\theta)\,b\right] &= \sum_{\tau} p(\tau;\theta)\,\nabla_\theta \log p(\tau;\theta)\,b \\ &= \sum_{\tau} p(\tau;\theta) \frac{\nabla_\theta p(\tau;\theta)}{p(\tau;\theta)}\,b \\ &= \sum_{\tau} \nabla_\theta p(\tau;\theta)\,b \\ &= \nabla_\theta\!\left(\sum_{\tau} p(\tau;\theta)\,b\right) \\ &= b\,\nabla_\theta\!\left(\sum_{\tau} p(\tau;\theta)\right) = b\,\nabla_\theta(1) = 0. \end{aligned} \]

So subtracting the baseline changes the variance, not the mean. To pull \(b\) outside the sum, it must be constant with respect to the sampled action.

Reward-to-Go and State-Dependent Baselines

The current objective makes each action interact with rewards at all times. What we really want is for an action to interact with the future rewards that come after it.

\[ \frac{1}{m} \sum_{i=1}^{m} \sum_{t=0}^{H_i-1} \nabla_\theta \log \pi_\theta\bigl(a_t^{(i)} \mid s_t^{(i)}\bigr) \left( \sum_{k=t}^{H_i-1} R\bigl(s_k^{(i)}, a_k^{(i)}\bigr) - b\bigl(s_t^{(i)}\bigr) \right). \]

A natural state-dependent baseline is the expected return from that state:

\[ b(s_t) = \mathbb{E}[r_t + r_{t+1} + \cdots + r_{H-1}] = V^{\pi}(s_t). \]

This is exactly the quantity we want: \(V^\pi(s_t)\) tells us how much reward the current policy is expected to obtain on average from state \(s_t\).

Estimating the Value Function

The key practical question is how to estimate \(V^\pi(s_t)\). Here are two approaches using a neural network value function.

1) Monte Carlo Value Estimate

  • Initialize a value network \(V_{\phi_0}^{\pi}\).
  • Collect trajectories \(\tau_1, \ldots, \tau_m\).
  • Regress the value network onto the empirical return.
\[ \phi_{i+1} \leftarrow \arg\min_{\phi} \frac{1}{m} \sum_{i=1}^{m} \sum_{t=0}^{H_i-1} \left( V_\phi^{\pi}(s_t^{(i)}) - \sum_{k=t}^{H_i-1} R\bigl(s_k^{(i)}, a_k^{(i)}\bigr) \right)^2. \]

The network learns to predict the total reward observed after being in a given state.

2) Temporal-Difference Value Estimate

  • Initialize a value network \(V_{\phi_0}^{\pi}\).
  • Collect transition data \(\{s, s', r\}\).
  • Fit the network to a bootstrapped target.

Fitted value iteration:

\[ \phi_{i+1} \leftarrow \arg\min_{\phi} \sum_{(s,s',r)} \left\|r + V_{\phi_i}^{\pi}(s') - V_\phi^{\pi}(s)\right\|_2^2 \]

This makes the value at state \(s\) match the immediate reward plus the value of the next state according to the current estimate.

Monte Carlo vs. TD for Estimating \(V^\pi\)

The Monte Carlo estimator is unbiased, but it is often not very sample efficient. The TD estimator is usually more sample efficient because it exploits Bellman structure.

\[ V^{\pi}(s) = \sum_{a} \pi(a \mid s) \sum_{s'} P(s' \mid s, a) \left[ R(s,a,s') + \gamma V^{\pi}(s') \right]. \]

By computing target values from this Bellman relationship and regressing onto them, TD value estimates can extract a learning target from every transition.

Why TD Can Be More Sample Efficient

  1. TD reuses previously learned information. Suppose the agent has already learned \(V(s_{t+1}) \approx 100\). After seeing a single transition from \(s_t\) to \(s_{t+1}\) with reward \(2\), TD can infer \(V(s_t) \approx 2 + \gamma 100\). It reuses knowledge already stored in the value function.
  2. TD targets usually have lower variance. A Monte Carlo return contains randomness from every future transition: \[ G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots. \] The TD target \[ r_t + \gamma V(s_{t+1}) \] still contains randomness from the immediate transition, but replaces the rest of the random trajectory with an average prediction.

Example. Suppose entering \(s_{t+1}\) produces either \(+100\) or \(-100\) with equal probability. Then \(V(s_{t+1}) = 0\). Monte Carlo targets from \(s_t\) may swing between approximately \(+100\) and \(-100\), so many episodes are needed for those returns to average toward zero. Once TD has learned that \(V(s_{t+1}) \approx 0\), every transition into \(s_{t+1}\) gets a target near \(r_t + \gamma \cdot 0\), which is much less noisy.

The tradeoff is that the TD estimate is biased whenever the bootstrap value \(V(s_{t+1})\) is wrong. This is the classic bias-variance tradeoff: less variance and faster reuse of data in exchange for bootstrapping bias. This does not necessarily mean TD converges to the wrong answer, because the source of bias changes over time as the value estimate improves.

Good Choices for the Baseline

  • Constant baseline: \[ b = \mathbb{E}[R(\tau)] \approx \frac{1}{m} \sum_{i=1}^{m} R(\tau^{(i)}). \]
  • Optimal constant baseline: \[ b = \frac{ \sum_i \left\|\nabla_\theta \log p\bigl(\tau^{(i)};\theta\bigr)\right\|^2 R(\tau^{(i)}) }{ \sum_i \left\|\nabla_\theta \log p\bigl(\tau^{(i)};\theta\bigr)\right\|^2 }. \] This minimizes variance among constant baselines, although in practice it is usually only a minor improvement.
  • State-dependent expected return: \[ b(s_t) = V^{\pi}(s_t). \] This compares the realized return after taking an action to the return the current policy would have expected from that state.
